# 栖序 1.9.2 · 全屏回到播放器本身

这次更新集中修复影音模式的全屏行为，目标很明确：**视频正常进入播放器原生全屏，但只占满栖序当前窗口；栖序这个外层窗口本身不改变大小和位置。**

## 播放器全屏重新适配

- **B 站只使用真正的“全屏”按钮：** 适配 `.bpx-player-ctrl-full`，明确排除“网页全屏”按钮 `.bpx-player-ctrl-web`。
- **YouTube 也使用播放器真正的全屏按钮：** 通过 Chromium 可信输入触发 `.ytp-fullscreen-button`，不再由页面脚本制造 Fullscreen。
- **不再用容器伪装全屏：** B 站或 YouTube 原生全屏没有成功时会保留正常布局并提示重试，不再用直接 `requestFullscreen()` 的兜底路径制造“看起来全屏、但播放器控制不完整”的状态。
- **字幕层不再改写网站 Fullscreen：** 双语字幕继续挂在播放器容器里，但不再重写 `HTMLVideoElement.requestFullscreen`，避免改变网站原生全屏行为。
- **用户自己点全屏不会二次触发：** 网站已经进入原生全屏时，栖序只同步自己的界面状态，不会再触发一次全屏按钮，避免刚进入又退出、按钮失灵或播放状态跳变。
- **外层窗口保持原样：** 全屏期间只扩展内嵌网页视图到当前栖序窗口的内容边界，BrowserWindow 的位置、宽高和系统全屏状态都保持不变。
- **彻底禁止系统级全屏：** 主窗口和登录弹窗都禁止进入 OS 全屏，并在宿主与网页视图上启用 `disableHtmlFullscreenWindowResize`；即使播放器调用标准 Fullscreen API，也只让播放器铺满栖序当前窗口内容区。
- **Esc 与悬浮控制保留：** 退出全屏后恢复原布局；播放进度、字幕状态、空格播放暂停和方向键等网页键盘控制沿用当前会话。

## 稳定性修复

- 本地页面加载改为 Electron 的 `loadFile()` 路径，减少 Windows 本地路径解析差异。
- 增加仅测试环境使用的影音回归入口，可在原生待办宿主不可用时独立验证 Electron 影音逻辑，不影响正式版运行。
- 新增 B 站原生全屏回归测试，防止以后再次误用“网页全屏”或在 `enter-html-full-screen` 事件中重复触发全屏。

安装包：**Qixu-Setup-1.9.2-x64.exe**，Windows 10 / 11 x64。覆盖升级沿用现有数据目录，保留待办、书库、网站会话、阅读位置、观看进度、老板键和设置。

详细验收范围见 [测试记录](test-record-1.9.2.md)。第三方网站的播放器 DOM、字幕和登录流程仍可能随网站更新变化。
